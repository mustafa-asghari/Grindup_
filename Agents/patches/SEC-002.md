# Patch Note: SEC-002

## Worker personality

Security Worker - Paranoid Threat Hunter

## Issue

`POST /api/problems/scrape` was publicly callable and could trigger LeetCode fetches, OpenAI embeddings, Postgres writes, and ClickHouse inserts.

## Root cause

The route had no trusted admin or job credential gate before scraper work started, and its catch block returned raw error messages plus stack traces.

## Original proof example

```bash
curl -i -X POST http://localhost:3000/api/problems/scrape
```

## Original fix location

`apps/web/src/app/api/problems/scrape/route.ts` `POST` around lines 175-179 and catch block around lines 345-351.

## Original what to change

Add admin or job-secret authorization before work starts and hide stack traces in responses.

## Files changed

- `apps/web/src/app/api/problems/scrape/route.ts`
- `.env.example`
- `Agents/stat.json`
- `Agents/patches/SEC-002.md`

## Fix made

The patch changed the exact original fix location. `POST` now checks `Authorization: Bearer <secret>` against `PROBLEM_SCRAPE_SECRET` before `initClickHouse()`, external fetches, database writes, ClickHouse inserts, or embedding calls. Missing or invalid credentials return `401` immediately, and an unset secret fails closed. The catch block now logs server-side details but returns only `{ "error": "Problem scrape failed" }`.

I also documented `PROBLEM_SCRAPE_SECRET` in `.env.example` and added route-local TypeScript types needed for the requested route-specific ESLint command to pass without changing scraper behavior.

## Why this fix is minimal

It keeps the scrape success response shape unchanged (`success`, `count`, `message`) and does not add a new auth model. The only new trust boundary is a dedicated job secret for this maintenance endpoint.

## Result

Unauthenticated scrape requests are rejected before any expensive or mutating work starts, and HTTP 500 responses no longer expose stack traces or raw internal error messages.

## Compatibility notes

Authorized local or scheduled runs must set `PROBLEM_SCRAPE_SECRET` and send it as a Bearer token. Existing successful scrape JSON remains unchanged.
