# Patch Note: DB-003

## Worker personality

Database Worker - Data Integrity Engineer

## Issue

`getNextJob()` could hand the same queued submission job to concurrent workers.

## Root cause

The helper read the next queued row and then updated it by primary key in a separate Prisma operation, so two read-committed transactions could observe and return the same queued job.

## Original proof example

```ts
const id = await queueSubmission({ userId, problemId, code: "print(1)", language: "python" });
const [a, b] = await Promise.all([getNextJob(), getNextJob()]);
console.log(a?.id, b?.id, await prisma.submissionJobs.findUnique({ where: { id } }));
```

## Original fix location

`apps/web/src/lib/submission-queue.ts` `getNextJob` lines 50-74.

## Original what to change

Use an atomic claim operation with `FOR UPDATE SKIP LOCKED` or an `updateMany` claim predicate plus retry.

## Files changed

- `apps/web/src/lib/submission-queue.ts`
- `Agents/stat.json`
- `Agents/patches/DB-003.md`

## Fix made

The patch changed the exact original fix location. `getNextJob()` now uses one Postgres `UPDATE ... WHERE id = (SELECT ... FOR UPDATE SKIP LOCKED LIMIT 1) RETURNING ...` statement to claim the next queued row, set `status = 'processing'`, set `started_at = NOW()`, increment `attempts`, and return only `{ id, userId, problemId, code, language }`.

The same file also replaced existing explicit `any` JSON types with Prisma JSON types so the requested file-level ESLint command passes.

## Why this fix is minimal

The queue state model, public helper return shape, FIFO/priority ordering, and completion/failure paths are unchanged. The claim now happens in the database as a single atomic row-locking operation without schema or migration changes.

## Result

Concurrent claimers skip locked queued rows, so only one worker can receive a given queued job; another worker receives a different queued job or `null`.

## Compatibility notes

The helper still returns the same job object shape or `null`. The SQL uses the existing `submission_jobs` table and mapped column names from the Prisma schema.
