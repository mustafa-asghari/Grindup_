# Patch Note: SEC-001

## Worker personality

Security Worker - Paranoid Threat Hunter

## Issue

Runner and execute API allow unauthenticated code execution.

## Root cause

The web `/api/execute` route read the session but allowed anonymous requests to continue into body parsing, submission dispatch, and runner execution. The runner `/execute` endpoint accepted direct requests without a server-side credential, and the full-stack compose file published the runner on all host interfaces.

## Original proof example

```bash
curl -i -X POST http://localhost:8080/execute -H 'Content-Type: application/json' --data '{"code":"def solution(x): return x","language":"python","test_cases":[{"id":"t1","input":"x = 1","expected_output":"1","is_hidden":false}],"time_limit_ms":2000,"memory_limit_kb":256000}'
```

## Original fix location

`apps/web/src/app/api/execute/route.ts` `POST` around lines 60-65 and 107-120; `apps/runner/main.py` `execute_code` around lines 69-103; `compose.yml` runner service around lines 80-85.

## Original what to change

Require `session.user.id` before accepting `/api/execute`, send a shared runner token header from the web app, require that header in the runner, and stop exposing runner on all host interfaces in compose.

## Files changed

- `apps/web/src/app/api/execute/route.ts`
- `apps/runner/main.py`
- `compose.yml`
- `.env.example`
- `README.md`
- `REVIEWER_RUN_GUIDE.md`
- `Agents/stat.json`
- `Agents/patches/SEC-001.md`

## Fix made

The patch changed the exact original fix locations and added adjacent configuration/docs needed to preserve local review behavior. `/api/execute` now returns `401` before parsing the request body when `session.user.id` is absent, creates submissions only for authenticated users, and forwards `X-Runner-Token` when `RUNNER_SHARED_SECRET` is configured. The runner now rejects missing or invalid `X-Runner-Token` on `POST /execute` before the handler prepares Docker execution when `RUNNER_SHARED_SECRET` is set. The full-stack compose file sets the same local secret for web and runner and binds runner port `8080` to `127.0.0.1`.

## Why this fix is minimal

The change only gates the existing execution path at its two trust boundaries and wires one shared secret through existing environment configuration. It does not change the editor request shape, runner response model, supported languages, submission result processing, or unrelated API routes.

## Validation attempted

- `python3 -m py_compile apps/runner/main.py`: passed.
- `docker compose config`: passed; output shows `RUNNER_SHARED_SECRET` on both web and runner and runner host binding `127.0.0.1:8080`.
- `pnpm --filter @grindup/web lint`: failed due existing repo-wide ESLint debt, including many `no-explicit-any`, React hook, and unescaped entity findings across unrelated files. The original proof curl was not rerun because the Docker stack was not started in this Worker pass.

## Result

Unauthenticated web execution is rejected before request body parsing or runner dispatch. Direct runner `/execute` calls without the shared token return `401`, invalid tokens return `403`, and authenticated web execution can still reach the runner when web and runner share `RUNNER_SHARED_SECRET`.

## Compatibility notes

Authenticated editor execution keeps the same `/api/execute` payload and response flow. Local direct runner health checks remain available at `/health`; direct `/execute` review calls now need `X-Runner-Token` when `RUNNER_SHARED_SECRET` is set.
